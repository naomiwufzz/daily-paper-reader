## 摘要
能够预判用户需求并自主执行任务的主动型智能体作为数字助手具有巨大潜力，但缺乏真实的用户模拟框架阻碍了其发展。现有方法将应用程序建模为扁平的工具调用 API，未能捕捉数字环境中用户交互的有状态和顺序特性，使得真实的用户模拟难以实现。我们推出了主动型智能体研究环境（Pare），这是一个用于在数字环境中构建和评估主动型智能体的框架。Pare 将应用程序建模为具有有状态导航和状态依赖动作空间的有限状态机，供用户模拟器使用，从而实现了活跃用户模拟。在此基础上，我们提出了 Pare-Bench，这是一个包含 143 个多样化任务的基准测试，涵盖通信、生产力、日程安排和生活方式类应用，旨在测试上下文观察、目标推理、干预时机以及多应用编排能力。

## Abstract
Proactive agents that anticipate user needs and autonomously execute tasks hold great promise as digital assistants, yet the lack of realistic user simulation frameworks hinders their development. Existing approaches model apps as flat tool-calling APIs, failing to capture the stateful and sequential nature of user interaction in digital environments and making realistic user simulation infeasible. We introduce Proactive Agent Research Environment (Pare), a framework for building and evaluating proactive agents in digital environments. Pare models applications as finite state machines with stateful navigation and state-dependent action space for the user simulator, enabling active user simulation. Building on this foundation, we present Pare-Bench, a benchmark of 143 diverse tasks spanning communication, productivity, scheduling, and lifestyle apps, designed to test context observation, goal inference, intervention timing, and multi-app orchestration.

*   **研究背景**：目前的智能体大多是“响应型”（Reactive），即仅在用户发出明确指令后才行动。主动型智能体需要通过观察用户行为和环境变化来推断目标并预判需求。
*   **研究动机**：现有的评估框架（如将应用简化为扁平的 API 调用）无法模拟真实用户在数字设备上“逐屏导航”的有状态交互过程。缺乏真实的用户模拟器，导致无法评估智能体在动态交互中推断目标、把握干预时机以及与用户协作的能力。

### 2. 方法论：核心思想与关键技术
*   **Pare 框架**：建立了一个非对称的模拟环境。
    *   **用户侧（有状态 FSM）**：将应用建模为有限状态机（FSM）。模拟用户必须像真人一样通过“打开应用 -> 搜索 -> 点击 -> 执行”的顺序进行操作，动作空间受当前页面状态限制。
    *   **智能体侧（扁平 API）**：主动型助手可以直接访问后端 API，反映了现实中系统级助手的权限优势。
*   **Stackelberg POMDP 建模**：将交互形式化为领导者（用户）和追随者（智能体）的博弈模型。智能体观察用户的动作序列 $A_U$ 和环境事件 $E_t$，推断潜在目标 $G_U$。
*   **“观察-执行”（Observe-Execute）架构**：
    *   **观察模式**：智能体持续监测，仅使用只读工具，决定是“等待”还是“向用户发送建议”。
    *   **执行模式**：一旦用户接受建议，智能体切换到执行模式，利用全量 API 权限完成多步骤任务。
*   **交互机制**：引入了专门的 `AgentUserInterface` 应用，用于处理建议的发送、接受和拒绝。

### 7. 优点（亮点）

*   **生态完整**：不仅提供了框架，还配套了包含 143 个任务的基准测试和自动化的场景生成流水线。
*   **架构合理**：提出的“观察-执行”分离架构既保护了用户自主权（必须确认后执行），又提高了系统的运行效率。

### 8. 不足与局限
*   **模态限制**：目前基于 API 和文本工具调用，未涉及视觉（UI 截图）层面的多模态交互。
*   **用户模型偏差**：虽然做了消融，但 LLM 模拟的用户仍无法完全替代真实人类的复杂心理（如疲劳、情绪或个性化的信任偏好）。

*   **任务时长**：实验限制在 10 个回合内，可能无法覆盖需要跨越数天或超长路径的复杂主动协作场景。
