## 摘要
我们提出了经验证的多智能体编排（VMAO），这是一个通过验证驱动的迭代循环来协调基于大语言模型（LLM）的专业化智能体的框架。针对复杂查询，我们的系统将其分解为子问题的有向无环图（DAG），通过特定领域的智能体并行执行，利用基于 LLM 的评估来验证结果的完整性，并进行自适应重规划以弥补差距。主要贡献包括：(1) 在子问题 DAG 上实现具有自动上下文传播的依赖感知并行执行；(2) 采用基于 LLM 的验证器作为编排层协调信号的验证驱动自适应重规划；(3) 可配置的停止条件，用于平衡回答质量与资源消耗。在 25 个专家精选的市场研究查询中，与单智能体基准相比，VMAO 将回答完整性从 3.1 提升至 4.2，来源质量从 2.6 提升至 4.1（1-5 分制），证明了编排层验证是多智能体质量保证的有效机制。

## Abstract
We present Verified Multi-Agent Orchestration (VMAO), a framework that coordinates specialized LLM-based agents through a verification-driven iterative loop. Given a complex query, our system decomposes it into a directed acyclic graph (DAG) of sub-questions, executes them through domain-specific agents in parallel, verifies result completeness via LLM-based evaluation, and adaptively replans to address gaps. The key contributions are: (1) dependency-aware parallel execution over a DAG of sub-questions with automatic context propagation, (2) verification-driven adaptive replanning that uses an LLM-based verifier as an orchestration-level coordination signal, and (3) configurable stop conditions that balance answer quality against resource usage. On 25 expert-curated market research queries, VMAO improves answer completeness from 3.1 to 4.2 and source quality from 2.6 to 4.1 (1-5 scale) compared to a single-agent baseline, demonstrating that orchestration-level verification is an effective mechanism for multi-agent quality assurance.

*   **核心目标**：建立一个能够自动分解任务、并行执行、自我验证并根据反馈动态调整计划的闭环编排框架。

#### 2. 方法论：核心思想与技术细节
VMAO 提出了一个 **Plan-Execute-Verify-Replan（规划-执行-验证-重规划）** 的迭代循环框架：
*   **任务分解（Plan）**：将复杂查询分解为**有向无环图（DAG）**形式的子问题。每个节点包含子问题文本、指定的智能体类型、依赖关系和验证标准。
*   **并行执行（Execute）**：`DAGExecutor` 根据依赖关系识别“就绪”的任务并并行执行（默认并发数 $k=3$）。支持自动上下文传播，即上游结果会作为下游任务的输入。
*   **编排层验证（Verify）**：使用独立的 LLM 验证器评估结果的完整性（0-1 评分）、缺失维度和矛盾点。
*   **自适应重规划（Replan）**：根据验证结果决定是重试失败任务、引入新子问题填补缺口，还是合并现有结果。
*   **分层智能体架构**：将智能体分为三层：Tier 1（数据采集：RAG、Web、财务）、Tier 2（分析推理）、Tier 3（输出生成：文档、可视化）。
*   **停止条件**：引入五个可配置维度（完整性阈值、高置信度、收益递减、Token 预算、最大迭代次数）来平衡质量与成本。

*   **类别差异**：在**战略评估（Strategic Assessment）**类开放式查询中提升最显著（完整性提升 53%），因为这类任务最依赖迭代细化。

#### 7. 优点
*   **结构化强**：使用 DAG 管理依赖，比纯对话式 Agent 更具可解释性和可控性。

*   **成本与延迟**：Token 消耗极高，且 15 分钟的平均响应时间不适合实时交互场景。

*   **级联错误风险**：如果初始的 `QueryPlanner` 分解逻辑出现偏差，后续的验证环节可能无法完全纠正方向性错误。
