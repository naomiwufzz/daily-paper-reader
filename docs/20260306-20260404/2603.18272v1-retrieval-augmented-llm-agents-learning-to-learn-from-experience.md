## 摘要
虽然大语言模型（LLMs）推动了通用智能体的发展，但实现对未知任务的鲁棒泛化仍然是一个重大挑战。目前的方法通常依赖于微调，或者利用检索到的经验进行无需训练的记忆增强生成；然而两者都有局限性：微调往往难以外推到新任务，而经验检索的表现通常逊于有监督的基准模型。在这项工作中，我们提出将这些方法结合起来，并系统地研究如何训练检索增强的大语言模型智能体，以有效地在上下文中利用检索到的轨迹。首先，我们利用 LoRA 建立了一套鲁棒的有监督微调（SFT）方案，其性能优于几种最先进的智能体训练流水线。其次，我们对经验检索的关键设计选择进行了详细分析，确定了存储、查询和轨迹选择的最优策略。最后，我们提出了一种将经验检索集成到微调过程中的流水线。我们的结果表明，这种结合方法显著提高了对未知任务的泛化能力，为构建能够学习从经验中学习的智能体提供了一个可扩展且有效的框架。

## Abstract
While large language models (LLMs) have advanced the development of general-purpose agents, achieving robust generalization to unseen tasks remains a significant challenge. Current approaches typically rely on either fine-tuning or training-free memory-augmented generation using retrieved experience; yet both have limitations: fine-tuning often fails to extrapolate to new tasks, while experience retrieval often underperforms compared to supervised baselines. In this work, we propose to combine these approaches and systematically study how to train retrieval-augmented LLM agents to effectively leverage retrieved trajectories in-context. First, we establish a robust supervised fine-tuning (SFT) recipe using LoRA that outperforms several state-of-the-art agent training pipelines. Second, we provide a detailed analysis of key design choices for experience retrieval, identifying optimal strategies for storage, querying, and trajectory selection. Finally, we propose a pipeline that integrates experience retrieval into the fine-tuning process. Our results demonstrate that this combined approach significantly improves generalization to unseen tasks, providing a scalable and effective framework for building agents that learn to learn from experience.

论文关注的核心挑战是 **LLM 智能体在未知任务（Unseen Tasks）上的泛化能力不足**。
*   **背景**：目前的智能体主要依赖两种路径：一是**有监督微调（SFT）**，虽在分布内表现强，但遇到新任务时性能往往崩塌；二是**无需训练的记忆增强（RAG）**，通过检索过去经验辅助决策，但其表现通常逊于经过微调的基准模型。
*   **动机**：作者旨在探索如何将检索增强（RAG）与参数微调（LoRA）结合，构建一种既能保持分布内高性能，又能通过“学习如何利用检索到的经验”来应对新任务的智能体。

### 2. 方法论：ExpRAG 与 ExpRAG-LoRA
论文提出了 **ExpRAG (Experience Retrieval-Augmented Generation)** 框架，其核心思想是将智能体过去的交互轨迹（Trajectories）作为外部情节记忆。

*   **核心流程**：
    1.  **经验库构建**：离线收集智能体的交互轨迹 $\tau_i$，并使用编码器 $\phi$ 将其转化为向量索引。
    2.  **检索机制**：在推理的每一步（或初始步），根据当前任务描述和历史 $h_t$ 生成查询向量，检索 Top-K 条相关轨迹。
    3.  **上下文注入**：将检索到的轨迹格式化为 JSON 或文本块（Memory Block），注入到 LLM 的系统提示词中。
    4.  **ExpRAG-LoRA（训练阶段）**：这是本文的关键创新。在微调阶段，模型不仅学习预测动作，还学习在**包含检索到的轨迹**的上下文中预测动作。这迫使模型学会“参考”上下文中的经验，而不是仅仅死记硬背训练数据。
*   **关键技术细节**：支持**静态检索**（仅在任务开始时检索一次）和**动态检索**（每一步根据新观察刷新检索结果）。

### 3. 实验设计
*   **数据集/场景**：
    *   **ALFWorld**：家庭清洁与操纵任务。
    *   **ScienceWorld**：复杂的科学实验任务（如电路连接、化学混合）。
*   **Benchmark 设置**：作者将任务分为 **Easy（简单/训练任务）** 和 **Hard（困难/测试任务）**。Hard 任务包含训练中未见的动作类型或目标。
*   **对比方法**：
    *   **Zero-shot**：无检索、无微调。
    *   **纯 LoRA**：标准有监督微调。
    *   **Inference-only ExpRAG**：在冻结的指令微调模型上直接应用检索。
    *   **现有 SOTA**：对比了 ReAct、Reflexion、Mem0、Agent-FLAN 等多种学术界已发表的智能体框架。

### 4. 资源与算力
*   **硬件**：所有模型训练均在 **单张 80GB NVIDIA A100 GPU** 上完成。
*   **模型规模**：使用了 Ministral 3-8B、Gemma 3-4B、Qwen 2.5-7B 以及 Qwen 2.5-7B-1M（长文本版）。
*   **训练时长**：论文提到在 ALFWorld 上训练 9 个 Epoch，在 ScienceWorld 上训练 29 个 Epoch。作者特别强调了“延迟泛化”现象，即在验证集 Loss 开始上升后，智能体的实际任务成功率往往还会继续提升，因此进行了长达 50 个 Epoch 的实验观察。

### 5. 实验数量与充分性
*   **实验规模**：非常充分。
    *   涵盖了 4 种不同的开源模型底座。
    *   进行了大量的消融实验，包括 Top-K 数量（1, 2, 4）、检索模式（静态 vs 动态）、索引组成（匹配 vs 不匹配）、轨迹格式（JSON vs 文本）。
    *   每组实验均运行了 3 个随机种子并报告了标准差。
*   **客观性**：作者首先建立了一个极强的 LoRA 基准（甚至超过了许多复杂的强化学习方法），确保了对比的公平性，避免了在弱基准上刷分的嫌疑。

### 6. 主要结论与发现
*   **检索增强微调的优越性**：ExpRAG-LoRA 在 Hard 任务上的表现远超纯 LoRA。例如在 ALFWorld 的 Hard 任务中，纯 LoRA 成功率仅为 34.4%，而 ExpRAG-LoRA 达到了 88.5%。
*   **学习从经验中学习**：通过在训练中加入检索内容，模型学会了提取经验中的模式，这种能力可以迁移到完全陌生的任务类型中。
*   **动态检索的局限**：动态检索虽然理论上更精准，但由于频繁刷新上下文，可能导致“上下文不稳定性”，在某些场景下表现不如静态检索。
*   **长训练周期的必要性**：智能体微调存在类似“Grokking（顿悟）”的现象，即使 Loss 不再下降，任务成功率仍可能大幅攀升。

### 7. 优点与亮点
*   **简单且有效**：没有引入复杂的强化学习算法或多层记忆控制器，仅靠 RAG + SFT 的组合就刷新了多个基准。
*   **系统性分析**：对检索的每一个环节（Query 怎么写、Key 怎么存、K 取多少）都做了详尽的工程化验证。
*   **揭示了训练动力学**：指出了智能体训练中验证集 Loss 与实际成功率的脱节，对后续研究具有重要的实践指导意义。

### 8. 不足与局限
*   **经验来源依赖**：实验中使用的经验库是由专家脚本生成的。在现实场景中，如果只有智能体自身产生的低质量/失败轨迹，该方法的鲁棒性仍有待验证。
*   **推理开销**：引入 Top-K 轨迹显著增加了 Prompt 的长度（Token 数增加 3-10 倍），导致推理延迟和计算成本上升。
*   **任务范围限制**：目前仅在文本交互式环境中验证，尚未在多模态或真实机器人场景中测试。
*   **索引缺失风险**：当检索不到任何相关经验时，ExpRAG-LoRA 的表现会退化，甚至可能略逊于标准 LoRA（由于训练/推理分布不一致）。
