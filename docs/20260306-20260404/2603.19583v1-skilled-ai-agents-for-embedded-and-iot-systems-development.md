## 摘要
大语言模型（LLMs）和智能体系统在自动化软件开发方面展现出巨大潜力，但由于软件逻辑与物理硬件行为之间的紧密耦合，将其应用于硬件在环（HIL）嵌入式和物联网（IoT）系统仍面临挑战。由于时序约束、外设初始化要求或特定硬件行为，成功编译的代码在部署到真实设备上时仍可能失败。为应对这一挑战，我们引入了一种面向 HIL 嵌入式开发的基于技能的智能体框架，以及 IoT-SkillsBench，这是一个旨在系统评估真实嵌入式编程环境下 AI 智能体的基准测试。IoT-SkillsBench 涵盖了三个具有代表性的嵌入式平台、23 种外设以及三个难度级别的 42 个任务，每个任务在三种智能体配置（无技能、LLM 生成技能和人类专家技能）下进行评估，并通过真实硬件执行进行验证。通过 378 次硬件验证实验，我们表明，包含结构化专家知识的简洁人类专家技能可以在不同平台上实现近乎完美的成功率。

## Abstract
Large language models (LLMs) and agentic systems have shown promise for automated software development, but applying them to hardware-in-the-loop (HIL) embedded and Internet-of-Things (IoT) systems remains challenging due to the tight coupling between software logic and physical hardware behavior. Code that compiles successfully may still fail when deployed on real devices because of timing constraints, peripheral initialization requirements, or hardware-specific behaviors. To address this challenge, we introduce a skills-based agentic framework for HIL embedded development together with IoT-SkillsBench, a benchmark designed to systematically evaluate AI agents in real embedded programming environments. IoT-SkillsBench spans three representative embedded platforms, 23 peripherals, and 42 tasks across three difficulty levels, where each task is evaluated under three agent configurations (no-skills, LLM-generated skills, and human-expert skills) and validated through real hardware execution. Across 378 hardware validated experiments, we show that concise human-expert skills with structured expert knowledge enable near-perfect success rates across platforms.

*   **软硬件紧耦合**：代码即使通过编译，也常因时序偏差、外设初始化顺序错误或硬件特定行为而在真实设备上运行失败。

#### 2. 论文提出的方法论
核心思想是构建一个**基于技能（Skills-based）的智能体框架**，将复杂的硬件知识提炼为紧凑、可操作的“技能文档”。
*   **技能定义**：每个技能是一个结构化的 Markdown/YAML 文件，包含特定外设或框架的编程模式、初始化约束和常见错误模式，而非原始文档的堆砌。
*   **智能体架构（三节点）**：
    1.  **Manager 节点**：充当项目规划者，根据任务需求从技能库中检索并筛选相关技能。
    2.  **Coder 节点**：充当嵌入式工程师，利用筛选出的技能生成核心固件代码（如 `.c` 或 `.ino`）。
    3.  **Assembler 节点**：处理平台相关的脚手架工作，生成 `CMakeLists.txt`、`prj.conf` 或设备树（Device Tree）映射文件，确保项目可直接编译。
*   **核心流程**：任务输入 -> 技能检索 -> 代码生成 -> 自动化项目组装 -> 硬件部署验证。

研究者构建了 **IoT-SkillsBench** 基准测试，具有以下特征：

*   **23 种外设**：涵盖 GPIO、ADC、PWM、I2C、SPI、1-Wire 等多种接口。
*   **42 个任务**：分为基础控制（L1）、协议级通信（L2）和系统级集成（L3）三个难度等级。
*   **对比配置**：

*   **实验规模**：共进行了 **378 组硬件验证实验**（42 任务 × 3 技能配置 × 3 平台）。每个任务重复执行 5 次以评估稳定性。
*   **充分性**：实验覆盖了主流的嵌入式架构（AVR, Xtensa, ARM）和开发框架，任务难度梯度明显。

#### 6. 论文的主要结论与发现
*   **专家技能的决定性作用**：配备人类专家技能的智能体在所有平台上实现了**近乎 100% 的成功率**，显著优于其他配置。
*   **LLM 自生成技能的局限**：自动生成的技能往往会引入噪声或强化错误的假设，导致性能甚至低于“无技能”基准，且 Token 消耗最高。
*   **平台差异**：Arduino 任务最易解决；Zephyr 平台由于依赖复杂的设备树配置，对 LLM 挑战最大。
*   **硬件边界**：部分失败源于物理限制（如电压不匹配），这是纯软件层面的智能体无法解决的。

#### 7. 优点
*   **真实性高**：坚持“硬件在环”验证，揭示了编译成功不代表运行成功的行业痛点。
*   **Token 效率**：证明了“精简的专家知识”比“海量的原始文档”更有效，降低了推理成本。
*   **解耦设计**：Assembler 节点的设计有效分离了逻辑开发与复杂的环境配置。

#### 8. 不足与局限
*   **技能编写成本**：人类专家技能的编写需要深厚的领域知识，难以在短时间内覆盖所有新兴硬件。

*   **样本规模**：虽然 378 组实验在硬件验证中已属不易，但相比纯软件基准测试，其统计样本量仍有提升空间。
