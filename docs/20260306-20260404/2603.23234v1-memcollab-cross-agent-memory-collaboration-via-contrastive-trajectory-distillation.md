## 摘要
基于大语言模型（LLM）的智能体依赖记忆机制来复用过去解决问题经验中的知识。现有方法通常以单智能体的方式构建记忆，将存储的知识与单个模型的推理风格紧密耦合。在异构智能体的现代部署中，一个自然的问题随之而来：单个记忆系统能否在不同模型之间共享？我们发现，在智能体之间简单地迁移记忆往往会降低性能，因为此类记忆将任务相关知识与智能体特有的偏置纠缠在一起。为了应对这一挑战，我们提出了 MemCollab，这是一个协作记忆框架，通过对比不同智能体在同一任务上生成的推理轨迹来构建与智能体无关的记忆。这一对比过程蒸馏出了抽象的推理约束，这些约束捕捉了共享的任务级不变性，同时抑制了智能体特有的伪影。我们还引入了一种任务感知检索机制，根据任务类别对记忆访问进行条件化处理，确保在推理时仅使用相关的约束。在数学推理和代码生成基准测试上的实验表明，MemCollab 在包括跨模型家族设置在内的多种智能体中，一致地提高了准确性和推理效率。我们的结果表明，协作构建的记忆可以作为多种基于 LLM 的智能体的共享推理资源。

## Abstract
Large language model (LLM)-based agents rely on memory mechanisms to reuse knowledge from past problem-solving experiences. Existing approaches typically construct memory in a per-agent manner, tightly coupling stored knowledge to a single model's reasoning style. In modern deployments with heterogeneous agents, a natural question arises: can a single memory system be shared across different models? We found that naively transferring memory between agents often degrades performance, as such memory entangles task-relevant knowledge with agent-specific biases. To address this challenge, we propose MemCollab, a collaborative memory framework that constructs agent-agnostic memory by contrasting reasoning trajectories generated by different agents on the same task. This contrastive process distills abstract reasoning constraints that capture shared task-level invariants while suppressing agent-specific artifacts. We further introduce a task-aware retrieval mechanism that conditions memory access on task category, ensuring that only relevant constraints are used at inference time. Experiments on mathematical reasoning and code generation benchmarks demonstrate that MemCollab consistently improves both accuracy and inference-time efficiency across diverse agents, including cross-modal-family settings. Our results show that the collaboratively constructed memory can function as a shared reasoning resource for diverse LLM-based agents.

### 2. 方法论：MemCollab 框架
MemCollab 的核心思想是通过**对比推理轨迹（Contrastive Trajectory Distillation）**来过滤模型偏见，提取通用的推理约束。

*   **对比记忆构建（Contrast-Derived Memory Construction）**：
    *   **轨迹配对**：让两个异构智能体（如一个大模型 A_s 和一个小模型 A_w）解决同一个任务，收集它们的推理轨迹。
    *   **偏好选择**：根据 ground-truth 判定轨迹的对错，形成（正确轨迹 $\tau^+$，错误轨迹 $\tau^-$）配对。
    *   **对比分析**：利用大模型作为总结者，对比 $\tau^+$ 和 $\tau^-$。识别出错误轨迹中的“违规模式”（Violation patterns）和正确轨迹中的“推理不变性”（Reasoning invariants）。
    *   **抽象约束提取**：将对比结果转化为规范化的推理约束，格式为：“执行 [不变性]；避免 [违规模式]”。这些约束使用抽象概念（如变量隔离、案例枚举）而非具体数值。
*   **任务感知检索与推理（Task-Aware Retrieval）**：
    *   **任务分类**：在构建阶段，为每个记忆条目打上任务类别标签（如代数、数论、代码生成等）。
    *   **条件检索**：推理时，先对新查询进行分类，仅在同类任务的子集中检索最相关的 Top-p 条记忆，以减少噪声干扰。
    *   **引导推理**：将检索到的抽象约束作为 Prompt 的一部分，引导智能体进行推理。

*   **强模型亦受益**：强模型（32B）在使用协作记忆后，性能也有进一步提升，说明协作记忆能减少系统性错误。

*   **任务感知的必要性**：预先进行任务分类再检索，比单纯的向量相似度检索效果更好，能有效过滤无关噪声。

### 7. 优点与亮点
*   **解耦偏见**：通过对比学习的思想解决记忆迁移中的“风格纠缠”问题，这是一个非常新颖且具有实际部署价值的视角。
*   **抽象化表达**：记忆内容不是原始轨迹，而是高度蒸馏的“准则”，这使得记忆库非常轻量且易于跨模型理解。
*   **即插即用**：不需要对模型进行微调，通过 Prompt 工程即可实现记忆增强。

### 8. 不足与局限
*   **依赖强模型进行蒸馏**：对比分析过程需要一个性能较强的模型（如 32B 或更高）来生成高质量的抽象约束，这在完全去中心化的弱模型集群中可能难以实现。
*   **静态记忆库**：目前的实验主要基于预先构建的记忆库，对于在线学习和记忆的实时动态更新（Long-term evolution）探讨较少。
*   **任务覆盖范围**：虽然涵盖了数学和代码，但在更具主观性或开放性的任务（如创意写作、多轮对话）上的表现尚未验证。
