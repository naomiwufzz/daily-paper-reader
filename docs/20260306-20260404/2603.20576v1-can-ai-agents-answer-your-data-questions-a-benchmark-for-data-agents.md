## 摘要
企业用户日益依赖 AI 智能体通过自然语言查询其数据。然而，构建可靠的数据智能体仍然具有挑战性，因为现实世界的数据通常分散在多个异构数据库系统中，存在不一致的引用，且信息埋藏在非结构化文本中。现有的基准测试仅解决该问题的个别环节——例如，将自然语言问题转换为 SQL 查询，或针对上下文提供的微型表格回答问题——但并未评估跨多个数据库系统集成、转换和分析数据的完整流程。为了填补这一空白，我们提出了数据智能体基准测试（Data Agent Benchmark, DAB），该基准基于对六个行业企业数据智能体工作负载的形成性研究。DAB 包含跨 12 个数据集、9 个领域和 4 个数据库管理系统的 54 个查询。在 DAB 上，表现最好的前沿模型（Gemini-3-Pro）的 pass@1 准确率仅为 38%。我们对五种前沿大语言模型（LLM）进行了基准测试，分析了它们的失败模式，并为未来的数据智能体开发总结了经验。我们的基准测试和实验代码已发布在 github.com/ucbepic/DataAgentBench。

## Abstract
Users across enterprises increasingly rely on AI agents to query their data through natural language. However, building reliable data agents remains difficult because real-world data is often fragmented across multiple heterogeneous database systems, with inconsistent references and information buried in unstructured text. Existing benchmarks only tackle individual pieces of this problem -- e.g., translating natural-language questions into SQL queries, answering questions over small tables provided in context -- but do not evaluate the full pipeline of integrating, transforming, and analyzing data across multiple database systems. To fill this gap, we present the Data Agent Benchmark (DAB), grounded in a formative study of enterprise data agent workloads across six industries. DAB comprises 54 queries across 12 datasets, 9 domains, and 4 database management systems. On DAB, the best frontier model (Gemini-3-Pro) achieves only 38% pass@1 accuracy. We benchmark five frontier LLMs, analyze their failure modes, and distill takeaways for future data agent development. Our benchmark and experiment code are published at github.com/ucbepic/DataAgentBench.

### 2. 方法论与核心思想
该研究通过**形成性研究（Formative Study）**定义了数据智能体的四大核心挑战，并据此构建了 **DAB (Data Agent Benchmark)**：
*   **四大核心挑战**：
    1.  **多数据库集成**：跨不同数据库系统（SQL 和 NoSQL）进行连接。
    2.  **格式错误的连接键**：处理 ID 前缀不一、空格干扰或缩写不匹配等现实“脏数据”。
    3.  **非结构化文本转换**：从长文本字段中提取或分类出结构化属性。
    4.  **领域知识**：应用无法从模式中直接推断的业务定义（如金融波动率计算）。
*   **构建流程**：
    1.  收集 12 个开源数据集，涵盖金融、医疗、电商等 9 个领域。

    3.  **异构部署**：将数据分布在 PostgreSQL、MongoDB、SQLite 和 DuckDB 中。
    4.  **智能体架构**：采用 **ReAct 模式**，为智能体提供 `list_db`、`query_db`、`execute_python` 和 `return_answer` 四种工具。

### 3. 实验设计
*   **数据集/场景**：包含 12 个数据集（如 `stockmarket`、`crmarenapro`、`pancancer_atlas` 等），共 54 个复杂自然语言查询。

*   **案例研究**：对比了生产级平台 **PromptQL** 与基准 ReAct 智能体的表现。

### 4. 资源与算力
*   **算力说明**：论文未提及模型训练所需的 GPU 资源，因为其评估的是现有的前沿 API 模型。

*   **实验规模**：每个查询在每个模型上运行 50 次独立试验，这在智能体评估中是非常充分的，能够有效抵消 LLM 输出的随机性。
*   **客观性与公平性**：
    *   所有 ground-truth 答案均基于原始未扰动数据通过 Python 脚本确定，避免了 LLM 评分的主观性。
    *   提供了“提示文件（Hints）”作为变量，以区分“缺乏背景信息”和“推理能力不足”导致的失败。
    *   涵盖了闭源与开源、高性能与轻量化等多种模型。

### 6. 主要结论与发现
*   **性能堪忧**：最强模型 Gemini-3-Pro 的 **pass@1 仅为 38%**，即使尝试 50 次，最高准确率也不超过 69%。
*   **失败模式分析**：85% 的错误源于**错误的规划（Planning）**或**错误的实现（Implementation）**，而数据源选择错误（Data Selection）仅占 15%。
*   **正则依赖陷阱**：所有智能体在处理文本提取时都过度依赖正则表达式（Regex），当面对复杂的自然语言日期或实体时表现极差。
*   **成本效益**：GPT-5-mini 表现出极高的性价比，以 Gemini-3-Pro 1/20 的成本达到了 30% 的准确率。
*   **探索策略**：表现好的智能体通常分配约 20% 的工具调用用于数据探索（如查看模式、采样数据）。

### 7. 优点与亮点
*   **真实性极高**：基准测试的设计直接源于对六个行业真实企业用户的调研，而非学术假设。
*   **端到端评估**：不同于以往只测 SQL 生成，DAB 评估了从发现数据、编写异构查询、Python 处理到得出结论的全链路能力。
*   **失败分类学**：提出了一套针对数据任务的失败模式分类（FM1-FM5），为后续改进提供了清晰的路线图。

### 8. 不足与局限
*   **规模限制**：54 个查询虽然质量极高且经过人工验证，但相比于 Spider 等数千个查询的基准，样本量相对较小。
*   **评估偏向**：验证脚本主要检查答案是否包含 ground-truth 字符串，这可能导致“高召回、低精确”的评分偏差（即智能体返回一堆错误信息中夹杂一个正确答案也会判对）。
*   **静态环境**：未包含实时 API 集成（因其不可重复性）和开放式分析建议（因其难以自动评分），这两者也是企业真实场景的重要组成部分。
